# codex-transcribe — спецификация

## 1. Назначение

`codex-transcribe` — Python-пакет и одна команда CLI:

```text
аудио → codex-transcribe → текст
```

Команда принимает один аудиовход, выполняет декодирование, подготовку, распознавание и сборку результата. Для распознавания используется существующий ChatGPT transcription backend и авторизация Codex.

Пакет устанавливает все зависимости для обработки медиа через `pip` или `uv`. Целевые платформы: Windows x86-64, macOS x86-64 и arm64, Linux x86-64; Python 3.10 или новее. На них не требуются системные Git, FFmpeg, FFprobe, компилятор или отдельный сервер. Внешние предпосылки: Python, установщик пакетов, действующий Codex login и доступ к сети.

## 2. Вход

- `INPUT` — путь к локальному файлу или `-` для бинарного stdin.
- Формат определяется по содержимому, независимо от имени и расширения файла.
- Принимается любой контейнер и кодек, который декодируют поставляемые с пакетом медиакомпоненты. Видеофайл принимается, если содержит аудиопоток.
- При нескольких аудиопотоках выбирается первый. Отсутствие аудиопотока, пустой ввод, повреждённые, зашифрованные и недекодируемые данные завершаются ошибкой.
- Запись без распознанной речи может дать пустой текст.

## 3. CLI

```text
codex-transcribe [--output PATH] [--format text|json]
                 [--language CODE] [--auth-file PATH] INPUT
```

- `--output PATH`, `-o PATH`: записать результат в файл. Без флага результат выдаётся в stdout.
- `--format text|json`: формат результата; по умолчанию `text`.
- `--language CODE`: подсказка языка для backend. Без флага язык определяется автоматически.
- `--auth-file PATH`: явный путь к файлу авторизации Codex.
- `--help` и `--version`: справка и версия установленного пакета.

Текстовый результат кодируется в UTF-8 и оканчивается одним переводом строки. JSON-результат — один объект UTF-8: `schema_version` равен `1`, `status` равен `completed`, `text` содержит строку, `duration_seconds` содержит неотрицательное число секунд выбранного аудиопотока. Ход обработки и диагностика пишутся только в stderr.

Код выхода `0` означает, что весь вход обработан и результат выдан. При любом неуспехе код ненулевой; stdout остаётся пустым, а stderr содержит причину ошибки.

## 4. Обработка

1. Проверить вход, параметры и путь вывода. Путь вывода, совпадающий с входом напрямую, через symlink или hardlink, отклонить до отправки аудио.
2. Создать рабочий каталог текущего запуска. Скопировать вход в стабильный временный файл; при копировании обнаружить изменение исходного файла. stdin сохранить во временный файл.
3. Найти первый аудиопоток, декодировать его и нормализовать в формат загрузки backend.
4. Разделить нормализованное аудио на части, если запись превышает допустимый размер запроса. Размер каждой готовой части проверить до отправки с учётом multipart overhead.
5. Отправить части в исходном порядке. При `413` уменьшить проблемную часть и повторить запрос ограниченное число раз. При временной сетевой ошибке, `429` или `5xx` выполнить ограниченные повторы с задержкой.
6. Сохранить перекрытие на границах частей. Удалять только уверенно совпадающий текстовый дубль; при неоднозначности сохранять текст обеих частей.
7. Собрать полный текст в исходном порядке и выдать результат один раз после успешной обработки всех частей.
8. Удалить рабочий каталог при завершении или обработанном прерывании.

Потребление оперативной памяти не растёт пропорционально размеру входного файла. Для обработки требуется свободное дисковое место под временную копию и части.

## 5. Авторизация и backend

Файл авторизации ищется в следующем порядке: `--auth-file`, `CODEX_TRANSCRIBE_AUTH_FILE`, `$CODEX_HOME/auth.json`, `~/.codex/auth.json`. Пакет читает файл, не изменяя и не копируя его.

Токен не записывается в результат, временные файлы и диагностику. После `401` повтор разрешён только при наличии нового access token в файле авторизации.

Endpoint, заголовки, формат запроса и разбор ответа изолированы в модуле взаимодействия с backend. Используемый endpoint: `https://chatgpt.com/backend-api/transcribe`. Неожиданный ответ backend завершается ошибкой; пустой текст допускается только в корректном ответе backend.

## 6. Сохранность данных

- Результат в stdout или `--output` выдаётся только после полного успеха.
- `--output` записывается через временный файл в каталоге назначения и атомарную замену. При ошибке существующий файл назначения сохраняется.
- Исходный файл не перезаписывается командой.
- При обработанном SIGINT или SIGTERM отменяется активный HTTP-запрос, завершается дочерний медиапроцесс и удаляются временные файлы.
- Пакет не создаёт постоянное состояние и кэш ответов. Прерванный ввод при следующем запуске обрабатывается заново.

## 7. Поставка

- Исходный код и релизы размещаются на GitHub.
- Релиз содержит готовый Python wheel. Установка по прямой версионированной ссылке на wheel устанавливает все runtime-зависимости.
- README указывает поддерживаемые версии Python, операционные системы и архитектуры, команду установки, команду проверки версии и пример вызова.
- README содержит короткую инструкцию для агента: установить wheel, проверить `--version`, вызвать CLI с `--output`, вернуть путь к результату или сообщение об ошибке. Инструкция не требует читать или выводить `auth.json`.
- При установке в виде skill его инструкции вызывают тот же CLI. Обработка медиа, авторизация и запросы к backend остаются в Python-пакете.

## 8. Критерии готовности

1. На каждой целевой платформе установка wheel в чистой среде проходит без системных Git, FFmpeg и компилятора; после установки доступен `codex-transcribe --version`.
2. Аудиофайлы поддерживаемых медиакомпонентами форматов, файл с неверным расширением, бинарный stdin и видео с аудио обрабатываются одной командой. Недекодируемый вход даёт ошибку.
3. Короткая и длинная записи обрабатываются полностью. Для длинной записи сохраняются порядок частей и речь на границах; молчание допускает пустой результат.
4. Отсутствие авторизации, ошибка backend, нехватка места и обработанное прерывание не повреждают исходный файл и существующий `--output`; токен не появляется в диагностике.
5. Прямое совпадение и совпадение через symlink или hardlink между входом и `--output` отклоняются до сетевого запроса.
6. Проверки с подменённым HTTP transport покрывают CLI, подготовку медиа, деление, сборку, повторы, ошибки и сохранность данных. Совместимость с реальным endpoint проверяется отдельно с действующим Codex login без передачи секретов в CI.
7. README, wheel, CLI и инструкция для агента описывают одно проверенное поведение.
